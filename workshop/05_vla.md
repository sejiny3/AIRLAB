## 학습 목표

1. 모듈 3의 집기(마커 좌표 → IK → MoveIt)와 **학습된 정책의 집기**(이미지 → 관절 목표)가 어떻게 다른지 설명한다.

## 개념

### 지금 로봇은 어떻게 집고 있나

모듈 3의 `pick()`은 **계산**으로 집습니다.

```
 헤드 카메라 → ArUco 마커 검출 → 상자 위치·방향 (숫자)
            → 손 목표 자세 계산 (접근 15°, 손가락 방향) → MoveIt IK·계획 → 팔 궤적
```

정확하고 설명하기 쉽지만, **마커가 붙은 물체만** 집을 수 있고 물체 모양과 잡는 법을 사람이 코드로 정해 줘야 합니다.

### VLA (Vision-Language-Action)

VLA 정책은 숫자 좌표 없이 **카메라 영상(Vision)과 명령 문장(Language)을 보고 바로 관절 명령(Action)** 을 냅니다.

```
 머리 카메라 128×72 ┐
 손목 카메라 96×96  ├─▶ 신경망 ─▶ 앞으로 1초(10단계) 동안의 오른팔 관절 7개 + 손가락 목표
 명령 "pick up the red box" ┤                  + "다 집었다" 확률
 지금 관절각 8개   ┘         0.1초마다 다시 본다
```

RT-2, OpenVLA, π0 같은 큰 VLA는 수십억 개의 매개변수와 GPU가 필요합니다. 여기서는 같은 구조를
**아주 작게(매개변수 60만 개)** 만들어 노트북 CPU에서 약 1시간 만에 학습합니다.

### 무엇을 학습하고 무엇을 그대로 두나

| 단계 | 작업 모드 | VLA 집기 모드 |
|---|---|---|
| 계획 | LLM (Claude) | 같음 |
| 테이블까지 주행 | Nav2 | 같음 |
| 상자 앞 정렬 | ArUco 마커 정밀 접근 | 같음 (오른팔 기준) |
| **집기** | 마커 좌표 → MoveIt | **정책이 카메라를 보고** (`/joint_commands` 10 Hz) |
| 팔 접기, 놓기 | MoveIt | 같음 |

한 단계만 바꾸면 무엇이 좋아지고 나빠졌는지 정확히 비교할 수 있습니다.

### 모방 학습: 잘하는 사람을 따라 하기

1. **전문가**가 시연합니다. 여기서는 사람 대신 `expert.py`: 시뮬레이터가 아는 상자의 **실제** 위치로 IK를 풀어
   `pick()`과 같은 순서(손 벌리며 다가가기 → 비스듬히 밀어 넣기 → 쥐기 → 들기)로 움직입니다.
2. 시연마다 매 0.1초의 (카메라 영상, 관절각, 명령) → (전문가가 낸 관절 목표)를 기록합니다.
3. 신경망이 같은 입력에서 같은 출력을 내도록 학습합니다 (지도 학습, L1 손실).

정책은 실제 위치를 모릅니다. **영상만 보고** 전문가를 흉내 내야 합니다.

### 작은 차이가 쌓이는 문제와 세 가지 대책

정책이 조금만 틀려도 다음 장면은 시연에 없던 장면이 되고, 거기서 더 틀립니다 (compounding error).

| 대책 | 이 코드에서 |
|---|---|
| **넓게 모으기** | 네 테이블(하늘색 공급 테이블 셋, 나무색 작업대) × 그 테이블의 놓는 자리 × 상자 색 셋, 자리 중심에서 ±3 cm, 방향 ±45°, 로봇 정렬 오차 ±4×5 cm · ±8° 를 무작위로. 시연 절반은 다른 색 상자가 옆자리에 있다 (`sim.py`의 `TABLES`, `BOXES`, `SPREAD`, `DISTRACTOR`) |
| **흔들어 모으기 (DART)** | 시연 절반은 실제로 보내는 목표에 천천히 변하는 잡음을 더함. 기록하는 정답은 전문가 목표 그대로 → "어긋났을 때 돌아오는 법"이 데이터에 들어감 |
| **묶음으로 내기 (action chunking)** | 1단계가 아니라 10단계를 한 번에 예측하고, 겹치는 예측을 평균(temporal ensembling, ACT 논문) → 떨림이 줄고 한 번의 실수가 덜 퍼짐 |

### 정책의 구조 (`model.py`)

```
 이미지 → 합성곱 4층 → 공간 소프트맥스: 특징 지도 64개 각각이 "가장 강하게 반응한 위치 (x, y)"
                        → 128개 숫자 = "상자는 어디, 손가락은 어디"
 명령 → 단어마다 해시 → 단어 벡터 평균 (32)
 관절각 (8, 정규화)
 → 전부 이어 붙여 MLP 2층 (512) → 관절 목표 10×8 + "끝" 확률
```

공간 소프트맥스는 "어디에 있나"를 직접 숫자로 뽑아서, 위치가 중요한 집기에 적은 데이터로도 잘 맞습니다.
단어 해시는 어떤 문장이 와도 벡터를 만들 수 있게 합니다 (LLM이 보낸 문장도 그대로 들어감).

> **언어는 정말 쓰이고 있나? (실험으로 확인한 정직한 한계)** 시연의 절반에는 집을 상자 옆자리에 **다른 색 상자**가
> 있고, 명령에는 집을 상자의 색이 들어갑니다. 평가에서 정책은 두 상자가 있을 때도 100% 맞는 상자를 집었습니다.
> 그런데 `evaluate --ask-other`로 **정렬한 상자가 아닌 옆 상자의 색을 말해 보면** 20번 모두 정렬한 상자를 집습니다
> ([실습 4](#실습-4-처음-보는-배치에서-평가)). 시연에서는 늘 "오른손 앞에 정렬된 상자 = 집으라는 상자"였기 때문에,
> 정책은 색 낱말 대신 **더 쉬운 단서(정렬 위치)** 를 배웠습니다. 학습된 모델이 의도와 다른 지름길을 배우는 것을
> shortcut learning이라고 합니다. 성공률 100%만 보고는 알 수 없고, 단서를 하나씩 어긋나게 만든 시험으로만 드러납니다.
> 언어가 꼭 필요하게 만드는 것이 과제 3입니다.

| 항목 | 값 |

| 손목 카메라 | `camera_wrist_right` (fovy 66°), 96×96 |

| 성공 | 집으라고 한 상자가 처음보다 3 cm 이상 올라감 (다른 상자를 들면 실패) |

### 2단계: 스크립트 전문가 (`expert.py`)

전문가는 모듈 3의 `pick()`과 같은 순서로 움직이지만 MoveIt 대신 **직접 푼 IK**를 씁니다.

**손 기준점(TCP)과 손 방향.** 손 끝 사이트(`right_ee_control_point`)에서 손가락 쪽(사이트의 −z)으로 0.14 m가 두 손가락 패드의
가운데입니다. 잡는 자세는 `pick()`과 같습니다: 앞으로 향하고 15° 아래로 숙인 접근 방향, 손가락은 상자의 마주 보는 두 면을
닫도록 상자 방향을 ±45° 안으로 접은 각도만큼 돌림.

**경유점과 시간** (0.1초 단위로 목표 하나씩, 모두 77개):

| 구간 | 시간 | 움직임 |
|---|---|---|
| reach | 2.5 s | tuck에서 경유점(사전 접근 자세 10 cm 위, 닿지 않으면 5 cm·0 cm 위)까지 **관절 공간** 보간, 동시에 손 벌리기 (−0.6 rad) |
| pre | 1.0 s | 경유점 → 사전 접근 자세 (상자 중심 1.5 cm 위에서 접근 방향 뒤로 10 cm, 위로 4 cm), **직선** |
| approach | 1.5 s | 사전 접근 → 잡기 자세, 직선 |
| close | 1.0 s | 손 닫기 (−0.6 → 0) |
| lift | 1.2 s | 8 cm 들기, 직선 |
| hold | 0.5 s | 그대로 (이 5단계가 "끝" 정답) |

직선 구간은 0.1초마다 점을 찍고 각 점에서 IK를 풉니다. 보간은 `smooth(t) = t²(3 − 2t)`로 시작과 끝을 부드럽게 합니다.

**감쇠 최소제곱(damped least squares) IK.** 목표 위치 p\*, 자세 R\*와 지금 값 p, R의 차이를 6차원 오차로 만들고
관절 7개를 고칩니다:

```
e  = [ p* − p ;  0.5 · rotvec(R* Rᵀ) ]          회전 오차는 축-각 벡터 (0.5 = 위치와 회전의 무게)
J  = [ Jp ; 0.5 · Jr ]   (6 × 7)                 mj_jac으로 구한 TCP의 위치·회전 자코비안
Δq = Jᵀ (J Jᵀ + λ I)⁻¹ e,   λ = 1e-4             특이점 근처에서도 터지지 않게 λ를 더함
q ← clip(q + clip(Δq, ±0.2 rad), 관절 범위)       오차 0.1 mm 아래가 되거나 100번(시작점 찾기는 300번)까지
```

tuck 자세는 IK 시작점으로 나빠서(팔이 접혀 있음) 사전 접근 자세는 지금 자세 → home(관절 4 = 90°) → 무작위 4개 순서로
시도하고 **처음 수렴한 것**을 씁니다. 같은 시작점을 먼저 쓰니 시연마다 팔 모양(팔꿈치 방향)이 같아져 배우기 쉽습니다.

### 3단계: 시연 녹화 (`record.py`)

시연 한 편 = `.npz` 파일 하나 (압축, 약 0.4 MB):

| 키 | 모양 | 뜻 |
|---|---|---|
| `head` | (77, 72, 128, 3) uint8 | 매 단계 머리 카메라 |
| `wrist` | (77, 96, 96, 3) uint8 | 매 단계 손목 카메라 |
| `state` | (77, 8) | 그때의 관절각 |
| `action` | (77, 8) | 그때 전문가가 보낸 관절 목표 (= 정답) |
| `done` | (77,) | 마지막 5단계만 1 |
| `instruction` | 문자열 | 영어 명령 7가지 틀 중 하나에 색을 넣은 것 (예: `grab the green box`) |
| `table`, `color`, `distractor` | 문자열, 문자열, bool | 어느 테이블, 어느 상자, 옆에 다른 상자가 있었나 |

- **DART 잡음**: 홀수 번호 시연은 실제로 보내는 목표에 `d_t = 0.85·d_(t−1) + N(0, 0.012²)` (관절마다, rad)를 더합니다.
  천천히 떠도는 잡음이라 팔이 전문가의 길에서 조금 벗어나고, 기록하는 정답은 잡음 없는 전문가 목표입니다.
- **버리는 시연**: 상자를 못 들었거나 IK가 경유점에 5 mm 넘게 못 닿은 시연 (1200개 중 45개).
- **병렬**: `multiprocessing` `spawn` 풀 6개. 프로세스마다 MuJoCo 모델과 렌더러를 하나씩 만듭니다 (OpenGL 문맥은 프로세스끼리 나눌 수 없음).

### 4단계: 정책 신경망 (`model.py`, PyTorch)

층별 모양 (배치 1개 기준):

| 층 | 머리 카메라 | 손목 카메라 |
|---|---|---|
| 입력 (0~1 → −0.5~0.5) | 3 × 72 × 128 | 3 × 96 × 96 |
| Conv 5×5, 보폭 2, 32채널 + GroupNorm(8) + ReLU | 32 × 36 × 64 | 32 × 48 × 48 |
| Conv 3×3, 보폭 2, 64채널 + GN + ReLU | 64 × 18 × 32 | 64 × 24 × 24 |
| Conv 3×3, 보폭 1, 64채널 + GN + ReLU | 64 × 18 × 32 | 64 × 24 × 24 |
| Conv 1×1, 64채널 (키포인트 지도 64장) | 64 × 18 × 32 | 64 × 24 × 24 |
| **공간 소프트맥스** | 128 (= 64개 × (x, y)) | 128 |

**공간 소프트맥스**는 특징 지도 한 장(k번째)을 화면 전체에 대한 확률로 바꾸고, 그 확률로 좌표의 평균을 냅니다:

```
p_k(i, j) = exp(f_k(i, j)) / Σ exp(f_k)          화면 좌표 x_j, y_i ∈ [−1, 1]
(x̂_k, ŷ_k) = ( Σ p_k(i, j)·x_j ,  Σ p_k(i, j)·y_i )
```

결과는 "k번째 특징이 화면 어디에 있나"라는 숫자 두 개입니다. 학습하면서 어떤 키포인트는 상자를, 어떤 것은 손가락 끝을
따라가게 됩니다. 그래서 GPU 없이, 시연 수백 개로도 위치를 배울 수 있습니다.

나머지 입력과 출력:

| 부분 | 계산 | 크기 |
|---|---|---|
| 명령 문장 | 영어 단어마다 `crc32(단어) mod 512` → `EmbeddingBag(512, 32, 평균)` | 32 |
| 관절각 | (값 − 평균) / 표준편차 (학습 데이터의 행동 통계, 체크포인트에 같이 저장) | 8 |
| 이어 붙이기 | 128 + 128 + 32 + 8 | 296 |
| MLP | Linear 296→512, ReLU, Linear 512→512, ReLU, Linear 512→81 | 81 |
| 출력 | 81 = 10단계 × 8관절(정규화된 목표) + "끝" 로짓 1 | |

매개변수: 머리 인코더 62,336 + 손목 인코더 62,336 + 단어 표 16,384 + MLP 456,273 = **597,329개**.

> 단어 해시는 영어 소문자만 봅니다. 한글 문장은 빈 문장으로 처리되므로, 작업 관리자는 정책에 영어 문장
> ("pick up the red box")을 보냅니다. 사용자의 한국어 명령은 Claude가 도구 호출로 바꿔 줍니다.

```python
# model.py (요약)
def forward(self, head, wrist, words, offsets, state):
    z = torch.cat([self.head_enc(head - 0.5), self.wrist_enc(wrist - 0.5),
                   self.words(words, offsets), (state - self.mean) / self.std], dim=1)   # (n, 296)
    out = self.trunk(z)                                                                 # (n, 81)
    return out[:, :-1].view(-1, CHUNK, ACTION_DIM), out[:, -1]                          # 묶음, "끝" 로짓
```

### 5단계: 학습 (`train.py`)

| 항목 | 값 |
|---|---|
| 학습 표본 | 시연의 **모든 단계 하나하나**가 표본 하나: (그 순간 영상 2장, 관절각, 문장) → 그 단계부터 10단계의 전문가 목표. 끝에서 모자라는 단계는 마지막 목표로 채움 |
| 데이터 크기 | 학습 1040편 = 80,080 표본, 검증 115편 (편 단위로 무작위 10%를 떼어 둠. 같은 편의 장면이 양쪽에 섞이면 검증이 너무 쉬워짐) |
| 손실 | `L1(예측 묶음, 정규화된 정답 묶음) + 0.1 × BCE("끝" 로짓, done)` |
| 최적화 | `AdamW`, 학습률 1e-3, weight decay 1e-4, `OneCycleLR` (처음 5% 동안 올렸다가 끝까지 천천히 내림) |
| 배치, 단계 | 64, 20,000단계 (= 약 16 에포크), CPU 8스레드, 한 단계 약 0.19초 → 약 65분 (다른 일을 같이 하면 더 걸림) |
| 데이터 증강 | 영상: 상하좌우 ±4픽셀 무작위 이동(가장자리 복제), 밝기·대비 ±10%. 관절각: N(0, 0.01 rad) 잡음 |
| 저장 | 500단계마다 검증, 검증 L1이 가장 낮으면 `~/airlab_vla/policy.pt` (`state_dict` + 정규화 통계 + 단계 + 검증 L1, 2.4 MB) |

```python
# train.py의 학습 한 단계
batch = train.batch(rng.integers(0, len(train), 64), augment=True)   # 무작위 표본 64개 + 증강
pred, done_logit = policy(head, wrist, words, offsets, state)
loss = F.l1_loss(pred, (chunk - policy.mean) / policy.std) + 0.1 * F.binary_cross_entropy_with_logits(done_logit, done)
opt.zero_grad(); loss.backward(); opt.step(); sched.step()
```

실제 학습 기록 (검증 L1, 정규화 단위. 1.0 ≈ 관절 표준편차 하나):

| 단계 | 500 | 1,000 | 2,000 | 4,000 | 8,000 | 12,000 | 16,000 | 20,000 |
|---|---|---|---|---|---|---|---|---|
| 검증 L1 | 0.126 | 0.098 | 0.071 | 0.064 | 0.052 | 0.046 | 0.040 | 0.0385 |

0.0385 × 관절 표준편차(0.2~0.66 rad) ≈ 관절마다 평균 0.4~1.4° 차이입니다 (앞으로 1초 동안의 10단계 전체 평균).

### 6단계: 실행 (`runner.py`) — 묶음 예측의 시간 평균

정책은 0.1초마다 앞으로 10단계를 예측합니다. 그러면 지금 이 순간에 대한 예측이 최근 10번의 호출에서 하나씩 쌓입니다.
그것들을 가중 평균해서 보냅니다 (ACT의 temporal ensembling):

```
k단계 전에 만든 묶음의 k번째 값 = 지금에 대한 그때의 예측 a_k
보낼 목표 = Σ w_i · a_i / Σ w_i,   w_i = exp(−0.1 · i),   i = 0이 가장 오래된 예측
```

오래된 예측에 조금 더 무게를 줘서 움직임이 매끄럽고, 한 번 튄 예측이 바로 팔을 흔들지 못합니다.
"끝" 확률(시그모이드)이 3단계 연속 0.5를 넘으면 멈춥니다. 한 번 계산에 CPU 약 4 ms (`torch.no_grad`, 4스레드).

### 7단계: ROS에 붙이기 (`vla_pick_node.py`)

```
작업 관리자 pick_object(red_box)  [pick_mode = vla]
  ├─ servo_to_marker(마커 7, GRASP_XY['right'])          ArUco로 상자를 오른손 앞에 (기존 그대로)
  ├─ /vla/pick  ←  "pick up the red box"                 skills.vla_pick()이 보내고 /vla/result를 최대 40초 기다림
  │     vla_pick 노드 (시뮬레이션 시간 10 Hz 타이머)
  │       /camera/image_raw 1280×720 → cv2.resize(INTER_AREA) → 128×72
  │       /wrist_camera/image_raw 96×96,  /joint_states → 8개 관절각
  │       PolicyRunner.act() → /joint_commands (JointState, 관절 이름 8개 + 목표)  → 브리지가 액추에이터 목표로
  │       "끝" 3번 연속 또는 15초 → /vla/result {ok, steps, finger, reason}
  └─ 성공이면 MoveIt으로 팔 tuck, 들고 있는 물체 = red_box  (실패면 손 벌리고 tuck)
```

- **성공 판정**: 정책의 "끝"만 믿지 않습니다. 마지막으로 보낸 손가락 목표가 −0.15보다 크고(닫는 중), 실제 손가락 각도의
  크기가 0.06보다 커야(물체에 걸려 덜 닫힘) 성공입니다.
- `pick:=vla`는 브리지의 머리 카메라를 5 → 10 Hz로 올리고 손목 카메라를 켭니다. 학습 때 매 단계 새 영상을 봤기 때문입니다.
- 정책은 오른팔로만 학습했으므로 VLA 모드에서는 상자가 어느 쪽에 있든 오른팔 기준으로 정렬합니다.

### ACT, LeRobot, 큰 VLA와 비교

| | 이 모듈 | ACT (Zhao 2023) | OpenVLA (2024) | π0 (2024) |
|---|---|---|---|---|
| 영상 인코더 | 합성곱 4층 + 공간 소프트맥스 (처음부터 학습) | ImageNet ResNet-18 | DINOv2 + SigLIP | PaliGemma의 SigLIP |
| 언어 | 단어 해시 + 임베딩 평균 | 없음 | Llama 2 7B | PaliGemma (Gemma 2B) |
| 행동을 내는 부분 | MLP, 10단계 묶음을 한 번에 | 트랜스포머 디코더 + CVAE, 묶음 | 행동을 토큰(256칸)으로 하나씩 생성 | flow matching "행동 전문가", 50단계 묶음 |
| 매개변수 | 60만 | 약 8천만 | 70억 | 약 33억 |
| 학습 | 노트북 CPU 약 65분, 시연 1,155개 | GPU, 과제당 시연 50개 정도 | GPU 수십 장, 시연 약 97만 개 | GPU 대규모, 사전학습 + 과제별 미세조정 |

**LeRobot**(Hugging Face)은 ACT, Diffusion Policy, π0 같은 정책과 데이터셋 형식, 학습 스크립트를 모아 둔 프레임워크입니다.
이 모듈의 `record.py` → `train.py` → `evaluate.py`는 LeRobot의 "데이터 수집 → 학습 → 평가" 흐름을 작게 손으로 짠 것이라,
구조를 이해한 뒤 LeRobot으로 옮기면 같은 시연으로 ACT를 학습해 비교해 볼 수 있습니다 (GPU 권장).

```bash
supply_2      policy 33/33 (100%)   expert 33/33 (100%)
supply_3      policy 23/23 (100%)   expert 23/23 (100%)
with 2nd box  policy 43/43 (100%)   expert 43/43 (100%)
work_table    policy 29/29 (100%)   expert 29/29 (100%)
policy 100/100 (100%)   expert 100/100 (100%)   978 s
```

이 저장소에서 학습한 정책(시연 1155개, 20000단계)의 결과입니다. 다른 상자를 든 적은 한 번도 없고, 정책은 전문가와 거의 같은
7~8초(70~81단계)에 집습니다. `--table supply_1` 처럼 한 테이블만 시험할 수 있습니다.

**언어 확인 실험.** 이제 일부러 단서를 어긋나게 합니다. 두 상자가 있는 배치에서 로봇은 한 상자에 정렬하고, 명령은 **옆 상자**의 색을 말합니다:

```bash
$ ros2 run airlab_vla evaluate --ask-other --episodes 20
episode   0  supply_3   lined up with red  , asked for blue  -> lifted the lined-up box
...
named box: 0/20, lined-up box: 20/20, nothing: 0/20
```

정책은 20번 모두 **정렬한 상자**를 집었습니다. 색 낱말을 읽지 않고 "오른손 앞의 상자를 집는다"를 배운 것입니다
(시연에서는 그 둘이 늘 같았으니까요). 위의 100/100은 틀린 숫자가 아니지만, **무엇을 보고** 맞혔는지는 이렇게 단서를
떼어 놓는 시험을 해야 알 수 있습니다. 실제 시스템에서는 작업 관리자가 집을 상자의 마커로 정렬하므로 이 지름길로도 맞게
동작하지만, 정렬 없이 "여럿 중 하나를 말로 골라 집기"를 하려면 과제 3처럼 데이터를 바꿔야 합니다.

방을 넓히기 전(테이블 둘, 빨간 상자 하나)의 비교 실험도 남겨 둡니다. 무엇이 성공률을 만들었는지 보입니다:

| 학습 데이터 (방을 넓히기 전) | 공급 테이블 | 작업대 | 실패 모양 |
|---|---|---|---|
| 공급 테이블 시연 297개 | 48/50 (96%) | **0/20** | 공급: 손이 접근 시작 자세에서 **멈춤**(stall) 2번 · 작업대: 2초 만에 "다 집었다" |
| 두 테이블 시연 583개 | 48/48 (100%) | 52/52 (100%) | 없음 |

멈춤은 모방 학습에서 흔한 실패입니다. 전문가의 움직임은 경유점마다 부드럽게 서다가 다시 출발하는데, 정책 입장에서는
"멈춰 있는 장면"에서 "계속 서 있기"도 그럴듯한 답이라 거기에 갇힌 것입니다. 이 실험에서는 시연을 늘리자 사라졌습니다.

✅ **체크포인트 5-3**: 정책의 성공률과 `--ask-other` 결과를 적고, 정책이 무엇을 보고 상자를 고르는지 설명했다.

## 실습 5. 대시보드 VLA 집기 모드

```bash
$ ros2 run airlab_dashboard dashboard_launcher
```

http://localhost:8080 → 모드 **VLA 집기 (작업 + 학습된 집기 정책)** → 연결. 터미널에서 직접 켜려면:

```bash
$ ros2 launch airlab_manipulation bringup.launch.py planner:=true dashboard:=true pick:=vla
```

`pick:=vla`가 하는 일:

| 무엇 | 바뀌는 것 |
|---|---|
| 브리지 | 헤드 카메라 5 → 10 Hz, 손목 카메라 `/wrist_camera/image_raw` 켜기 (정책은 매 단계 새 영상으로 학습) |
| `vla_pick` 노드 | 정책을 불러 `/vla/pick`(명령 문장)을 기다림 → 0.1초마다 `/joint_commands` → 끝나면 `/vla/result` |
| 작업 관리자 | `pick_object`에서 오른팔 기준으로 정렬한 뒤 `pick()` 대신 `vla_pick()` 호출 |

"빨간 상자를 작업대로 옮겨줘"를 보내고, 대시보드의 **VLA 집기 정책** 카드에서 손목 카메라 영상과 "다 집었다" 확률을 보세요.
이어서 "초록 상자를 먼저 작업대 왼쪽에 놓고, 그다음 파란 상자를 오른쪽에 놓아줘", "상자를 모두 원래 자리에 돌려놓고 원위치로 와"처럼
모듈 4의 명령을 그대로 보내면 집기는 모두 정책이 합니다 (작업대의 왼쪽 자리 상자도 오른팔 기준으로 정렬해서 집음).

강사 노트북에서 대역(`llm:=scripted`)으로 "상자를 모두 작업대에 모아" → "모두 제자리로 돌려놔"를 보내 정책 집기 **6/6** 성공
(세 테이블과 작업대의 세 자리, 74~88단계), 놓기까지 12단계 모두 성공했습니다.

![VLA 집기 모드: 1번 공급 테이블에서 정책이 빨간 상자를 집은 직후. 아래 카드에 손목 카메라와 결과(성공 · 91단계)](slides/src/assets/dashboard_vla.jpg)

`vla_pick`은 정책이 "다 집었다"고 말해도 그대로 믿지 않습니다. **손을 닫으라고 명령했고, 손가락이 끝까지 닫히지 못하고
멈췄을 때(물체가 끼어 있음)** 만 성공으로 보고합니다. 처음에는 손가락 각도만 봤는데, 공급 테이블만 학습한 정책이 작업대에서
손을 벌린 채 "다 집었다"고 했을 때 벌린 손도 각도가 커서 성공으로 잘못 보고됐습니다. 학습된 부품의 출력은 이렇게
**다른 신호로 한 번 더 확인**해야 합니다.

✅ **체크포인트 5-4**: VLA 모드에서 상자 두 개 이상을 작업대로 옮기고, 다시 원래 자리로 가져다 놓았다.

## 과제

**과제 1. 데이터는 얼마나 필요한가.** 시연 50개, 100개로 각각 학습해(`--demos`로 폴더 지정, 파일 일부만 복사)
성공률을 표로 만드세요. 학습 단계 수는 같게 둡니다.

**과제 2. 무엇을 보고 집나.** `model.py`에서 손목 카메라 입력을 0으로 바꿔(`wrist * 0`) 다시 학습하고 평가하세요.
머리 카메라만으로는 왜 어려울까요? (힌트: 시연 사진에서 손이 상자를 가리는 때)

**과제 3. 언어가 꼭 필요하게.** 지금은 정렬 위치만 봐도 맞는 상자를 고를 수 있어서 정책이 색 낱말을 무시합니다.
`sim.py`의 `reset()`에서 두 상자가 있을 때 로봇을 **두 상자 사이**(가운데 기준 ±2 cm 안 무작위)에 정렬하고,
전문가가 명령한 색의 상자로 손을 뻗게 해 다시 녹화·학습하세요. 그다음 `evaluate --ask-other`에서 "named box"가 늘어나는지
보세요. (힌트: 오른팔이 닿는 범위가 좁으니 `GRASP_XY`에서 옆으로 너무 멀어지는 배치는 전문가의 IK가 걸러 냅니다.
버린 시연 수를 확인하세요.)

**과제 4. 멈춤 다시 만들고 고치기.** `record --table supply_1 --episodes 300`으로 한 테이블 시연만 모아 학습하고
`evaluate --table supply_1`, `--table work_table`로 평가해 위 표(방을 넓히기 전)와 비슷한 일이 생기는지 보세요. 멈춘 배치를 `--video`로 본 뒤 (1) `expert.py`에서
경유점 사이 `smooth()`를 빼 손이 서지 않고 이어서 움직이게, (2) 정책 입력에 "지금까지 걸린 시간"을 넣기 중 하나로
시연 수를 늘리지 않고 멈춤을 줄일 수 있는지 보세요.

**도전 과제. 더 넓은 정렬 오차.** `SPREAD`를 두 배로 늘리고 평가만 다시 하세요 (학습은 그대로). 어디서부터 실패하나요?
그 배치를 시연에 넣어 다시 학습하면 회복되나요?
